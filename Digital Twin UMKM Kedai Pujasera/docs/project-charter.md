# 2. Project Charter

[⬅️ Latar Belakang dan Ide](ide-proyek.md) &nbsp;|&nbsp; [Berikutnya: Stakeholder Register ➡️](stakeholder-register.md)

---

Project Charter adalah dokumen ringkas yang menyatakan apa yang akan dikerjakan, mengapa dikerjakan, dan sampai sejauh mana pekerjaan itu berlaku.

| Komponen | Uraian |
|---|---|
| **Nama proyek** | Pengembangan Versi Digital Kedai Pujasera |
| **Studi kasus** | UMKM Kedai Pujasera, yang menjual jus, es teh, minuman sachet, nasi ayam caplak, nasi goreng, dan menu lainnya |
| **Latar belakang** | Kedai memiliki menu beragam, sementara pelanggan membutuhkan informasi menu, harga, dan kedai yang mudah diakses. Kelompok merencanakan versi digital untuk menjawab kebutuhan tersebut |
| **Permasalahan** | 1. Informasi menu dan harga belum terpusat di satu media digital<br>2. Produk belum ditampilkan dengan foto yang memadai<br>3. Informasi kedai belum tersaji rapi<br>4. Belum ada media digital resmi untuk memperkenalkan kedai |
| **Tujuan** | Merencanakan versi digital Kedai Pujasera yang menampilkan menu, foto produk, harga, dan informasi kedai, serta menyusun dokumen perencanaan proyek |
| **Solusi yang diusulkan** | Website informasi Kedai Pujasera yang memuat menu, foto produk, harga, informasi kedai, dan informasi relevan lainnya |
| **Ruang lingkup** | Penyusunan dokumen perencanaan, analisis kebutuhan, perancangan, pengembangan, pengujian, dan dokumentasi website informasi |
| **Target pengguna** | Pelanggan dan calon pelanggan Kedai Pujasera; pemilik/pengelola kedai sebagai pihak yang memantau informasi |
| **Stakeholder** | Pemilik/pengelola kedai, pelanggan, karyawan kedai, tim proyek (Kelompok 11), dan dosen pengampu |
| **Hasil yang diharapkan** | 1. Dokumen perencanaan lengkap (Project Charter, Stakeholder Register, WBS)<br>2. Rencana versi digital yang siap dilanjutkan ke analisis dan perancangan<br>3. Repositori GitHub sebagai tempat kerja tim |
| **Batasan proyek** | 1. Tahap saat ini terbatas pada perencanaan<br>2. Data menu, harga, foto, dan info kedai bergantung pada pemilik/pengelola<br>3. Pelaksanaan mengikuti waktu dan ketentuan mata kuliah<br>4. Sumber daya terbatas pada anggota kelompok |

## Cakupan Proyek

| ✅ Termasuk | ❌ Tidak termasuk |
|---|---|
| Dokumen perencanaan (charter, stakeholder register, WBS) | Layanan pemesanan dan pembayaran online` |
| Pengumpulan data menu, harga, foto, dan informasi kedai | Pengelolaan stok dan pembukuan kedai |
| Perancangan tampilan dan struktur halaman | Pengadaan peralatan atau perangkat kedai |
| Pengembangan dan pengujian website informasi | Pengelolaan media sosial kedai |
| Dokumentasi proyek dan penggunaan Git/GitHub | Pemeliharaan jangka panjang setelah tugas selesai |

## Asumsi

1. Pemilik/pengelola kedai bersedia memberikan data menu, harga, foto, dan informasi kedai.
2. Anggota kelompok bekerja sesuai pembagian tugas.
3. Waktu pengerjaan mengikuti jadwal mata kuliah.

## Kriteria Keberhasilan (tahap perencanaan)

1. Project Charter, Stakeholder Register, dan WBS tersusun lengkap dan dipahami seluruh anggota.
2. Ruang lingkup tidak dikeberatkan oleh pemilik/pengelola kedai`.
3. Repositori GitHub dibuat dan dapat diakses seluruh anggota.
4. Pembagian tugas telah disepakati.

## Risiko Awal

| Risiko | Dampak | Rencana penanganan |
|---|---|---|
| Data menu, harga, atau foto terlambat/tidak lengkap | Pengembangan tertunda | Menyusun daftar data yang dibutuhkan dan memintanya sejak awal |
| Menu atau harga berubah setelah data dikumpulkan | Informasi tidak akurat | Konfirmasi ulang sebelum finalisasi; rancang agar mudah diperbarui |
| Beban kerja tidak merata | Pekerjaan terlambat | Pembagian tugas jelas di WBS dan pemantauan berkala |
| Anggota belum terbiasa dengan Git/GitHub | Berkas saling menimpa atau hilang | Latihan bersama dan aturan kerja sederhana |
| Foto produk kurang jelas | Tampilan kurang menarik | Menyepakati cara pengambilan foto yang sederhana |
| Harapan pemilik berbeda dengan rancangan tim | Hasil tidak sesuai kebutuhan | Meminta persetujuan pemilik sebelum pengembangan |
